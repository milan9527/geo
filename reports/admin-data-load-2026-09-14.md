# 后台数据加载失败修复 · 2026-09-14

后台登录成功后，研究列表 `/api/admin/research` 返回 502，导致页面显示“后台数据加载失败”。已部署 API 任务定义 32，并使用临时管理员完成真实登录和各页面验证。

## 原因

登录接口返回 200，十个初始化请求中只有研究列表失败；此前修复的统计接口正常返回 200。
生产日志明确指向 `_admin_research` 查询及 Aurora Data API 的 1 MB 返回结果上限。

研究列表原来一次读取最近 20 条完整研究记录。全库去重审核记录随内容增长，检查时审核字段合计 752,702 字节；该查询的 JSON 行合计 1,094,895 字节，已超过 1 MB。新增加的审核资料与定时任务输出使这条查询触及容量上限。

## 修复

- 研究列表、详情和证据读取采用 8,192 字符的分块，每次最多读取 8 块，再完整还原原来的 JSON 数据。
- 同一请求的分块和关联证据使用只读、可重复读快照，避免并发写入造成前后数据混用。
- 最近 20 条研究按时间和 ID 确定顺序，处理相同时间戳；单条审核或证据超过 1 MB 也可分块读取。
- 保留既有响应字段、审核记录及证据。网站正文、发布状态、网址和自动发布策略未因本次修复更改。

## 验证

- 4 项 PostgreSQL 回归测试通过：复现旧查询超限；最新 20 条完整返回；单条超大审核与证据、中文/emoji/引号/换行准确还原；空列表、404 和并发读取一致性。
- 新代码直接连接生产数据库，完整研究列表为 20 条、1,337,245 字节，约 1.65 秒返回；研究详情也正常。
- Chromium 真实登录后，10 个初始化接口全部返回 200。总览、内容、研究、采集、数据源、任务和设置均正常，研究列表显示 20 条；另验证 3 个详情接口。
- 刷新、重新载入后的会话恢复、退出登录通过，浏览器没有脚本异常。
- 原有 24 个已发布页面的状态、网址、正文和来源指纹一致；11 个永久重定向保持原样。
- 临时测试管理员及其会话已删除，临时凭据文件已清理。
