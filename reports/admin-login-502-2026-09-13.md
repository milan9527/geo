# 后台登录后 API 502 修复（2026-09-13）

## 原因

生产日志显示 `/api/admin/auth/login` 返回 HTTP 200，随后
`/api/admin/metrics?range=30d` 触发 Aurora Data API
`UnsupportedResultException: The result exceeds the size limit 1 MB.`。

统计接口一次读取整个统计周期及前一对比周期的访问记录。排查时有 710 条小时聚合记录，
其中 HLL 访客去重字段合计 971,280 字节，叠加其他字段及响应编码后超限。
请求处理异常使负载均衡器返回 502，而前端将后台初始化异常当成登录失败，重新显示登录页。

使用独立的临时测试管理员复现：登录返回 200，十个初始化接口中仅统计接口返回 502。
未修改原管理员账号、密码或权限。

## 修改

- 统计查询按每页 128 条读取，使用完整的复合主键/时间与 ID 作为下一页游标。
  不截断统计周期，不丢弃访客去重数据，业务事件也采用分页读取。
- 整个统计事务使用只读、可重复读快照，防止日志写入改变分页过程中的统计口径。
- 前端区分认证失败与数据加载失败：后者保留登录会话并显示“重新加载”按钮；
  真正收到 401 时才要求重新登录。
- 部署脚本增加 `--api-only`，支持单独滚动更新 API 容器。

## 回归验证

- `scripts/test_admin_metrics.py`：5 项通过。真实 PostgreSQL 测试数据可以复现超过
  1 MB 的旧查询；分页后 929 条访问记录和 401 条业务事件完整保留，统计响应与不受
  Data API 限制的完整查询一致。覆盖相同时间戳跨页、空结果以及并发写入的一致快照。
- `scripts/test_admin_login.py`：5 项 Chromium 测试通过。覆盖成功登录后遇到 502、
  已有会话恢复时遇到 502、无需再次输入密码即可重试、错误密码和过期会话。
- 使用生产 Aurora Data API 验证分页读取 710 条访问记录、106 条业务事件，
  访问请求合计 1,572，与同一快照中的数据库汇总相符。

可在隔离的本地 PostgreSQL 中执行统计回归：

```bash
METRICS_TEST_DATABASE_URL='postgresql://…' .venv/bin/python scripts/test_admin_metrics.py -v
```

浏览器回归需要在测试环境安装 Playwright 和 Chromium：

```bash
.venv/bin/python scripts/test_admin_login.py -v
```
